# 아이디어 후보 4안 (2026-10-22)

> 방향 1 = **혁신·실용** (기존엔 없던 기술, 있으면 확실히 편한 것) / 방향 2 = **가족 중심**.
> **[실측]** = 에뮬레이터에서 직접 확인, **[미검증]** = 가정, **[일반 지식]** = Pleos에서 확인 안 한 업계 일반 정보.
> 근거 문서: [sdk-probe-results.md](sdk-probe-results.md), [common-foundation.md](common-foundation.md), [idea-comparison.md](idea-comparison.md)

## 0. 모든 안에 적용되는 전제 (실측)

- **주행 중(D) 표시 경로가 에뮬레이터에 없음**: DO meta-data가 사이드로드 앱에서 인정되지 않고, 서드파티 heads-up도 뜨지 않는다 → **사용자와의 상호작용이 정차(P) 중에 일어나는 안**이 시연에 유리하다.
- **`requestTrip`(NAVI_ROUTE)**: 경로 안내를 시작하지 않고 거리·ETA·**도착 시 예상 SOC**·소비 에너지를 받는다. 약 0.2초, **Navigation 앱이 전면으로 올라오지 않음** [실측]. 예: 판교역 3.2km/740초/도착 59%, 강릉역 195km/8579초/도착 23%.
  도착 SOC는 SOC 속성이 아니라 배터리 에너지(`EV_BATTERY_LEVEL`, Wh) 기준으로 보임 [실측 추정]. 충전 경유(`RoutePointPoiType.EV_CHARGING`)가 결과에 들어오는지는 미확인.
- `requestRoute`/`requestRouteWithWaypoints`/`addWaypoint`는 Navigation 앱을 전면으로 올린다 (안내 시작 순간에만 쓰면 자연스러움). 경유지 최대 2개.
- 순정 내비가 이미 하는 것: 도착 잔량 %·왕복 예상, **배터리 부족 시 충전소 자동 경유**, 경고등은 아이콘만 표시 [실측].
- 4안 모두 **PRIVATE 퍼미션이 필요 없다**. 다만 Vehicle SDK 퍼미션은 앱마켓 사전 승인 대상(심사 기준).

## 방향 1 — 혁신·실용

### 1-A. 다음 동선 비서 (Trip-Chain Predictor)

**한 줄**: 시동을 걸면 오늘 갈 곳을 **순서까지** 먼저 제안하고, 한 번 누르면 경유지가 포함된 경로로 바로 출발한다.

| 항목 | 내용 |
|---|---|
| 문제 | 매일 반복되는 동선(출근 전 어린이집 → 회사, 퇴근길 마트 → 집)도 매번 목적지·경유지를 입력한다. 순정 내비는 최근 목적지·즐겨찾기 **단일 목적지 목록**만 준다 |
| 흐름 | ① 과거 운행에서 (요일·시간대·출발지 → 경유지 → 목적지) 체인을 학습 ② P + 경로 없음 + 앱 화면 → 상위 1~2개 제안 카드 "어린이집 → 회사 · 42분 · 도착 61%" (도착 SOC·ETA는 `requestTrip`으로 화면 전환 없이 계산) ③ 탭 → `requestRouteWithWaypoints` → 내비가 전면으로(곧 안내 시작) |
| SDK | NaviHelper: `requestTrip`[실측], `requestRouteWithWaypoints`(래퍼 구현, 실기 검증 전), `getCurrentLocationInfo`·`getRecentDestinationInfo`·`getBookmarkInfo`, `onRouteStarted`/`onWaypointChanged`/`onDestinationArrived` / Vehicle: Gear, SOC |
| 퍼미션 | CAR_DRIVE, CAR_ENERGY, NAVI_ROUTE, NAVI_ROUTE_SEARCH |
| 새로움 | 다중 경유 **체인**을 시간대별로 예측하고 도착 SOC까지 붙여 원터치로 출발. 단일 목적지 예측은 상용 지도 앱에 있음 [일반 지식] |
| 시연 | P 상태 화면만으로 가능. 학습 기록은 에뮬레이터에서 실제로 몇 번 운행해 쌓는다(진짜 이벤트, 더미 아님) |
| 리스크 | 콜드스타트(초기엔 즐겨찾기·최근 목적지만 — 에뮬레이터엔 비어 있음), 예측 정확도 설득, 위치정보 이용약관 필요 |
| 사업성 | 모든 운전자, **매일 사용** → Retention 강함. 경유지 제휴(카페·주차장), 프리미엄 |

### 1-B. 충전 출발 신호 (Ready-to-Go Charging)

**한 줄**: 충전기를 꽂으면, **다음 목적지까지 충분해지는 순간**을 계산해 "지금 출발해도 된다"고 알려준다.

| 항목 | 내용 |
|---|---|
| 문제 | 충전 중 "얼마나 더 해야 하나"를 감으로 판단 → 과충전(시간·요금·급속 80% 이후 저속·대기열 매너) 또는 부족 |
| 흐름 | ① 충전 포트 열림 + SOC 상승 감지 ② 다음 목적지 = 1-A의 예측 또는 즐겨찾기 → `requestTrip`을 주기적으로 호출해 **도착 SOC**를 얻음 (화면 전환 없음) ③ 사용자 여유분(예: 도착 15%) 충족 시점을 SOC 상승 속도로 예측 → "12분 뒤 출발 가능", 충족 시 큰 화면 표시 ④ 충전 기록 자동 저장 (ΔSOC × 용량 77.4kWh, 장소, 사업자) → 월 충전 가계부 |
| SDK | EvBattery: `registerEvBatteryStateOfCharge`·`registerEvChargePortOpen`·`getEvChargeSwitchState`·`getEvBatteryCapacity` [실측] / NaviHelper: `requestTrip`·`getCurrentLocationInfo`·`onChargerOperatorInfo` [실측] |
| 퍼미션 | CAR_ENERGY, CAR_INFO(배터리 용량), NAVI_ROUTE |
| 새로움 | 순정은 **경로 안내 중** 도착 잔량·충전 경유를 다루지만, **충전 중 '언제 빼도 되는지'**는 안 함 [실측 범위]. 일부 타사 차량에 유사 기능 있음 [일반 지식] → Pleos엔 없음 |
| 시연 | 충전 중 = 주차라 주행 규제와 무관 → 에뮬레이터에서 **완전 시연 가능**. 단 에뮬레이터는 충전 중 SOC가 저절로 오르지 않으므로 Virtual Console 슬라이더로 SOC·배터리 에너지를 함께 올린다 |
| 리스크 | EV 한정(타깃 축소), 충전 속도 추정 오차, 요금 데이터는 외부 API(선택, [미검증]) |
| 사업성 | EV 오너, 주 1~3회 충전 → 반복 사용. 충전 사업자 제휴·결제, 가계부 프리미엄 |

## 방향 2 — 가족 중심

### 2-A. 아이 탑승 모드 (Kid Onboard)

**한 줄**: 뒷좌석에 아이가 타면 **출발 전 30초 안전 체크**와 아이 맞춤 길·등하원 동선을 자동으로 준비한다.

| 항목 | 내용 |
|---|---|
| 문제 | 등하원·학원 이동은 매일 반복되고, 뒷좌석 상태(창문 잠금·벨트·온도)는 운전석에서 확인이 어렵다 |
| 흐름 | ① 2열 좌석 점유 감지 ② P에서 출발 전: 2열 창문 잠금, 2열 벨트 체결, 실내 온도 → 한 화면 "뒷창문 잠금 꺼짐 ⚠" ③ 경로: `RouteOption.COMFORTABLE`(편안한 길)·`SCHOOL_ZONE` + 학교/학원 체인 원터치 ④ 도착 후 P + 2열 여전히 점유 + 운전석 도어 열림 → "뒷좌석 확인" |
| SDK | Seat: `getCurrentSeatOccupancy`(5좌석)·`getCurrentSeatBeltBuckledState` [실측 Get 지원] / Window: 2열 잠금·위치 [실측] / HVAC 현재 온도 [실측 19.1℃] / Door / Gear / NaviHelper 경로 옵션·경유지 |
| 퍼미션 | CAR_SEATS, CAR_WINDOWS, CAR_CLIMATE, CAR_DOORS, CAR_DRIVE, NAVI_ROUTE, NAVI_ROUTE_SEARCH |
| 새로움 | "출발 전 뒷좌석 점검 + 아이 동선 + 편안한 길" 묶음. **하차 시 뒷좌석 알림 단독은 순정과 겹칠 수 있음** — 현대차 후석 승객 알림 [일반 지식], 플랫폼 TelltaleType에 `CHILD_PRESENCE_DETECTION_OFF` 존재 [실측] |
| 시연 | Virtual Console로 2열 점유·창문 잠금 조작 가능, 체크 화면은 P라 에뮬레이터 OK. **벨트 상태는 콘솔에서 조작 불가**. 주행 중 벨트 풀림 알림은 표시 경로가 막혀 제외 |
| 리스크 | 순정 기능 겹침, 아동 관련 데이터 민감성 |
| 사업성 | 영유아·초등 자녀 가구, **주 5일 사용** → Retention 높음. 학원·키즈 시설 제휴 |

### 2-B. 가족 여행 페이스메이커 (Family Road-Trip Pacer)

**한 줄**: 아이와 장거리를 갈 때 **휴게소·충전을 아이 리듬에 맞춰** 미리 짜 주고, 쉴 때마다 다음 구간을 안내한다.

| 항목 | 내용 |
|---|---|
| 문제 | 아이 동반 장거리는 60~90분마다 쉬어야 하고 EV는 충전도 겹친다. 순정은 **배터리 기준으로만** 충전소를 넣는다 [실측] — 아이 휴식·수유실·놀이시설은 고려 안 함 |
| 흐름 | ① 2열 점유로 가족 모드 판단 ② 출발 전 목적지 `requestTrip`(강릉: 195km·2시간 23분·도착 23% [실측]) → 총 시간으로 휴식 횟수 결정 ③ 경로상 휴게소 후보(수유실·놀이방·충전기) 중 아이 리듬과 충전 필요를 함께 만족하는 곳을 경유지로 최대 2개씩 제안 → `requestRouteWithWaypoints` ④ 휴게소 도착(`onWayPointArrived`) + P → "다음 구간 50분 · 다음 휴게소 OO(충전기 4·수유실)" + 다음 경유지 재계획 ⑤ 여행 기록(구간·휴식·충전) |
| SDK | Seat 점유, EvBattery, NaviHelper `requestTrip`·`requestRouteWithWaypoints`·`onWayPointArrived`·`onDrivingInfo`(경유지 충전소 여부·출력·충전기 수 [실측]) |
| 퍼미션 | CAR_SEATS, CAR_ENERGY, NAVI_ROUTE, NAVI_ROUTE_SEARCH |
| 외부 데이터 | 휴게소 편의시설 공공 데이터 [미검증] |
| 시연 | 출발 전 계획·휴게소 정차 화면 모두 P → 에뮬레이터 OK. 실제로 휴게소까지 "도착"하는 이벤트는 에뮬레이터 가속 주행 재현 실패로 **미확인** |
| 리스크 | 외부 데이터 품질, 경유지 2개 제한, 사용 빈도 낮음(주말·명절) |
| 사업성 | 가족 단위, 빈도는 낮지만 1회 가치 큼. 휴게소·충전 제휴. **2-A와 합치면 일상(등하원) + 이벤트(여행)로 Retention 보완** |

## 제안

- **방향 1이 실측 조건에 가장 잘 맞는다.** 1-A와 1-B는 같은 엔진(`requestTrip` + 동선 학습)을 공유하고, 상호작용이 모두 P에서 끝나 에뮬레이터 제약을 받지 않으며, 외부 데이터와 PRIVATE 퍼미션 없이 핵심이 돌아간다. 하나의 앱 **"출발 비서"**(평소엔 1-A, 충전 중엔 1-B)로 묶을 수 있다.
- **방향 2는 감성·창의성 점수에 유리**하다. 2-A + 2-B를 **"패밀리 모드"** 하나로 묶으면 빈도 문제를 보완하지만, 순정 기능 겹침(하차 알림)과 휴게소 데이터 검증이 선행 과제다.
- 결정 후 할 일: 고른 안의 핵심 시나리오 1개를 M2(11/10)까지 끝까지 동작시키고, CLAUDE.md §6·§9를 갱신한다.
