## 방향 1′ — 실용 (테슬라·순정에 없는 것)

### 1-C. 업무용 차량 운행기록부 자동 작성

**한 줄**: 계기판 누적거리와 출발·도착 위치를 자동으로 기록하고, 정차 중 한 번 탭으로 용도(출퇴근/업무/비업무)만 고르면 **세무 신고용 운행기록부**가 완성된다.

| 항목 | 내용 |
|---|---|
| 문제 | 법인차·개인사업자 업무용 승용차는 비용을 인정받으려면 운행기록부를 써야 하는데, 대부분 손으로 쓰거나 휴대폰 GPS 앱으로 추정한다 [일반 지식, 법령 세부·기준 금액 미검증]. 법인차 사적 이용 관리 관심도 커짐(법인 전용 번호판) [일반 지식] |
| 흐름 | ① D 진입 시 누적거리 기록 시작 ② P·운행 종료 시 종료 누적거리 + 출발·도착 주소 ③ 정차 화면에서 용도 원탭 — 즐겨찾기 OFFICE면 출퇴근, 반복 목적지는 학습해 자동 제안 ④ 월말 운행기록부 서식으로 내보내기 ⑤ 충전 포트·ΔSOC로 충전비 기록도 비용 증빙 보조 |
| SDK | Odometer `getCurrentDistanceDriven`/`registerDistanceDriven` [실측: 1234.0, 주기 콜백] · Gear [실측] · NaviHelper `getCurrentLocationInfo`(주소 "수정구 시흥동" 수준) [실측] · EvBattery(충전 기록) [실측] |
| 퍼미션 | CAR_DRIVE, CAR_ENERGY, CAR_INFO, NAVI_ROUTE |
| 차별점 | 휴대폰 앱은 GPS **추정** 거리이고 매번 켜야 한다. 차량 앱은 **계기판 값 그대로, 자동**. 테슬라 순정엔 세무 운행기록부 기능 없음 [일반 지식]. 현대 블루링크 주행 이력과 겹치는지는 [미확인] |
| 시연 | Virtual Console 누적거리 슬라이더 + 기어 P/D + 정차 화면 → **에뮬레이터에서 완결** |
| 리스크 | 법적 서식·요건 정확성(세무 검토), 내보내기 경로(이메일 로그인 또는 서버 필요 — 로그인은 정차 중에만), 타깃이 업무용 차량으로 한정 |
| 사업성 | B2B SaaS(차량당 월 구독), 법인 차량관리 솔루션 제휴. **운행마다 사용(사실상 의무)** → Retention 매우 높음. 시장 규모 수치는 기획서 작성 전 출처 확보 필요 |

### 1-D. 동승 비용 자동 정산 · 인증 카풀 기록

**한 줄**: 좌석 센서로 누가 어디서 타고 내렸는지 구간을 나누고, 실제 소비 전력으로 **1인당 비용을 계산해 송금 QR**까지 만든다. 기업에는 센서로 확인된 "인증 카풀" 리포트를 준다.

| 항목 | 내용 |
|---|---|
| 문제 | 출퇴근 카풀·동료 동승 비용은 대충 나누거나 기름값 기준으로 어림. EV는 전기 요금이 얼마 들었는지 더 모호. 기업 카풀 장려 프로그램은 자기 신고라 검증이 어려움 |
| 흐름 | ① 좌석 점유 + 해당 도어 열림/닫힘으로 탑승·하차 감지 ② 정차(P)마다 구간 분할, 위치 기록 ③ 구간별 에너지(ΔEV_BATTERY_LEVEL Wh 또는 ΔSOC×용량) × 단가 → 1인당 금액 (통행료는 SDK 미지원 → 수동) ④ 도착 후 정차 화면에 정산 + 송금 QR(송금 링크 형식 [미검증]) ⑤ 기업용: 센서 기반 탑승 인원·거리 리포트(탄소 절감) |
| SDK | Seat 점유 [실측: 2열 false 전환 수신] · Door [실측: 뒷문 1→0] · EvBattery 잔량·용량 [실측] · Gear · Odometer · NaviHelper 위치 |
| 퍼미션 | CAR_SEATS, CAR_DOORS, CAR_ENERGY, CAR_INFO, CAR_DRIVE, NAVI_ROUTE |
| 차별점 | 테슬라·순정에 동승 정산 없음 [일반 지식]. 휴대폰 정산 앱은 수동 입력, 탑승 검증 불가 |
| 시연 | 좌석 점유·도어를 콘솔로 조작 가능. 단 "탑승" 복귀 이벤트가 안 나는 에뮬레이터 이슈 → 시나리오를 "탑승 상태에서 출발 → 하차" 순서로 설계 |
| 리스크 | 실차 2·3열 점유 센서 유무(차종별) [미검증], 센서는 "누구"인지 모름(좌석에 사람 지정은 수동), 개인 시장은 니치 |
| 사업성 | 개인 무료 + 기업 카풀·ESG 리포트 B2B |

## 방향 2′ — 가족 (감성보다 기능)

### 2-C. EV 차박·캠핑 전력 플래너

**한 줄**: 밤새 공조를 켜고 자도 **내일 집까지 갈 수 있는지**를 실측 소모율과 실제 경로로 계산해, 기상 시 예상 배터리와 조정 방법을 알려준다.

| 항목 | 내용 |
|---|---|
| 문제 | 전기차 차박·캠핑·차 안 낮잠 때 공조를 켜면 배터리가 얼마나 줄고 내일 귀가가 가능한지 감으로 판단 → 방전 걱정에 공조를 끄거나(추위·더위), 반대로 다음 날 귀가 불가 |
| 흐름 | ① P + 공조 ON + 탑승 감지 → 캠핑 모드 제안 ② 실측 소모율(배터리 Wh 주기 콜백) × 남은 체류 시간 → 기상 시각 예상 SOC ③ 내일 목적지(집 즐겨찾기 등) `requestTrip` → "07:00 출발 시 도착 12% 예상" ④ 부족하면 "설정 온도를 1℃ 낮추면 +n%" 식 안내(공조 제어 SDK는 미오픈 → 안내만), 기준 이하로 떨어지면 정차 화면 경고 |
| SDK | EvBattery 잔량 Wh·SOC [실측: 1~3초 주기 콜백] · HVAC 전원·온도·팬·A/C [실측] · Seat 점유 · Window/Door(환기) · Gear · NaviHelper `requestTrip` [실측: 화면 전환 없음] |
| 퍼미션 | CAR_ENERGY, CAR_CLIMATE, CAR_SEATS, CAR_WINDOWS, CAR_DRIVE, NAVI_ROUTE |
| 차별점 | 현대 유틸리티 모드·테슬라 캠프 모드는 **공조 유지** 기능 [일반 지식]. **"내일 이 경로로 귀가 가능한가"를 실제 경로 기반으로 계산**해 주지는 않는 것으로 앎 [미확인 — 확인 필요] |
| 시연 | 전 과정이 정차 중 → **에뮬레이터에서 완결**. 배터리 감소는 콘솔 슬라이더로 단계적으로 내려 재현 |
| 리스크 | 순정 유틸리티 모드 화면과의 겹침 정도, 공조 제어 불가(안내만), 수면 중 알림 방식, 계절성 |
| 사업성 | EV 가족·차박 수요 [수치 미검증], 캠핑장·충전 제휴. 사용은 시즌·주말 위주 |

### 2-D. 통학차량 승하차 기록 · 하차 확인

**한 줄**: 학원·어린이집 통학차량이 정류장에 설 때마다 **좌석별 승하차를 자동 기록**하고, 운행 종료 시 좌석에 아이가 남아 있으면 종료 전에 확실히 막는다.

| 항목 | 내용 |
|---|---|
| 문제 | 어린이 통학차량은 운행 종료 시 하차 확인 의무와 하차확인장치(차량 뒤쪽 버튼) 설치 의무가 있다 [일반 지식, 법령 세부 미검증]. 승하차 기록·학부모 안내는 대부분 수기·전화 |
| 흐름 | ① 운행 시작(D) ② 정류장 정차(P)마다 좌석 점유 변화 + 도어 열림 → 승하차 기록(시각·주소) ③ 운행 종료(P + 시동 끄기 전) 시 점유 좌석이 남으면 정차 화면에 큰 경고, 확인 전 종료 불가 ④ 일일 운행·승하차 기록 자동 저장(관리자 제출용) ⑤ (2단계) 학부모 도착 알림 — 서버 필요 |
| SDK | Seat 점유 [실측] · Door [실측] · Gear · Odometer · NaviHelper 위치·경유지(정류장) |
| 퍼미션 | CAR_SEATS, CAR_DOORS, CAR_DRIVE, NAVI_ROUTE (정류장 경로를 쓰면 NAVI_ROUTE_SEARCH) |
| 차별점 | 기존 하차확인장치는 사람이 눌러야 하는 버튼, 순정 후석 승객 알림은 단건 알림 [일반 지식]. **정류장 단위 자동 기록 + 운영 리포트**가 차별점 |
| 시연 | 콘솔로 좌석 점유·도어 조작, 정차 화면에서 시연. 에뮬레이터는 5좌석 |
| 리스크 | 실제 통학차(3~4열)의 좌석 센서 커버리지 [미검증], 법정 장치를 **대체가 아닌 보조**로 포지셔닝, 아동 데이터 민감성, "탑승" 이벤트 에뮬레이터 이슈 |
| 사업성 | B2B(학원·어린이집 차량당 구독), 규제 기반 수요, 운영일 매일 사용 |

## 제안

- **1-C 운행기록부**가 2차 기준에 가장 잘 맞는다: 의무 기반 수요라 "있으면 확실히 편함"이 분명하고, 계기판 누적거리라는 **차량 앱만의 우위**가 있으며, 정차 화면에서 시연이 완결되고 외부 의존이 내보내기뿐이다.
- 가족 쪽에서는 **2-C 차박 전력 플래너**가 감성 없이 기능적이고, 1차에서 찾은 `requestTrip`(화면 전환 없는 도착 SOC)을 핵심에 쓰는 유일한 안이라 기술 활용 설명이 쉽다. 2-D는 사회적 의미가 크지만 실차 좌석 센서 커버리지가 미검증이라 리스크가 크다.
- 어느 쪽이든 기획서에 쓰기 전 **[일반 지식] 항목(법령·서식·순정 기능 범위·시장 규모)의 출처 확인**이 먼저다.
