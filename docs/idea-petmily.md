# 펫밀리 모드 — 아이디어 확장 (2026-10-22)

> "펫밀리"(반려동물 + 가족)를 하나의 제품으로 보고, 여정 단계별로 기능을 뽑았다. 이전 안: [idea-family-pet.md](idea-family-pet.md)
> **신호**는 실측으로 SDK에서 받는 것만 ([sdk-probe-results.md](sdk-probe-results.md)). **실현성** ◎ 지금 SDK로 핵심 동작 / ○ 외부 데이터·서버 필요 / △ 미검증 센서 의존.
> **설계 원칙**: 에뮬레이터는 주행 중(D) 화면이 가려지고 heads-up도 안 뜬다 [실측] → **모든 사용자 상호작용은 정차(P) 순간**에, 주행 중 일은 기록만 하고 다음 정차 때 보여준다.
> **[미검증]** 데이터 출처 미확인, **[일반 지식]** Pleos에서 확인 안 한 업계 정보.

## 탑승자 파악 (모든 기능의 바탕)
- 출발 시 원탭 "오늘 탑승: 아빠·엄마·아이·멍이" → 좌석 지도에 배치(아이 = 벨트 체결, 반려견 = 벨트 미체결 좌석).
- 좌석 점유는 실시간 수신 [실측]. 벨트는 Get 가능하지만 콘솔로 조작 불가 [실측]. 콘솔 "탑승" 복귀 이벤트가 서비스에서 안 나는 에뮬레이터 이슈 [실측] → 시연은 "탑승 상태에서 시작 → 하차(빈자리)" 순서로.

|---|---|---|---|---|---|

## 제품 구성안

### MVP (M2까지, 외부 데이터 없이 지금 SDK만으로)
| 순서 | 기능 | 시연 장면 (Virtual Console) |
|---|---|---|
| 1 | 탑승자 파악 + **출발 전 체크** (1 창문 잠금, 2 에어백, 3 견종 온도) | P에서 2열 창문 잠금 해제 → 경고, 잠금 → 해소 |
| 2 | **리드줄 하차 가드** (8) | D → P 전환 순간 화면 |
| 3 | **휴게소 롤콜** (9) | 2열 오른쪽(반려견) "빈자리" + 문 모두 닫힘 → "멍이 탔나요?" |
| 4 | **마지막 하차 지점 기록** (10) | 뒷문 열림 → 기록 카드 → 실종 공고 화면 |
| 5 | 주행 기록 → 다음 정차 때 요약 (6 창문 개방, 7 승차감) | 주행 중 창문·제동 조작 → P에서 요약 |

→ MVP는 퍼미션 CAR_SEATS·CAR_WINDOWS·CAR_DOORS·CAR_CLIMATE·CAR_SAFETY(에어백)·CAR_DRIVE·NAVI_ROUTE 정도, **PRIVATE 불필요**.

### 2단계 (공공 데이터·서버 확인 후)
13 목적지 동반 확인, 17 야간 응급 버튼, 12 휴식 리듬, 11 차내 대기 판단, 5 펫 매니저(동승자 폰), 14 방문 검증 지도.

## 왜 펫밀리가 "차여야만" 하나 (차량특화성 정리)
- **좌석 점유·창문 잠금·에어백·문 열림·기어 P 전환**은 폰이 모르는 신호다. 롤콜·리드줄 가드·창문 스위치 경고·마지막 하차 지점은 이 신호가 없으면 불가능.
- 순정은 사람 기준 안전 기능(안전벨트 경고·후석 알림)만 있고 **반려동물을 탑승자로 다루지 않는다** — 펫밀리 모드의 빈틈.

## 선행 확인
- 실차 2열 좌석 점유 센서가 **소형견 무게**에도 반응하는지 [미검증] → 반응 안 하면 롤콜은 명단 기반(원탭 확인)으로 대체.
- 견종별 적정 온도·창문 스위치 사고 등 근거 자료 출처.
- 2단계 공공 데이터(동반 장소·휴게소 편의시설·야간 진료기관·동물병원)의 존재와 품질.
